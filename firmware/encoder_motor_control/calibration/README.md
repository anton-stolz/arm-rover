# Clean Version: Magnetic Encoder Ultimate Synthesis

This folder contains the final, bug-free version of the advanced 5-parameter and 4Pi kinematic LUT calibration logic for the robot's magnetic encoders.

## Files
- `data/aufnahme_20260824_010724.csv`: The high-quality constant-speed recording used for calibration.
- `calibrate_and_plot.py`: The single, clean, highly readable Python script that performs the calibration and exports the results to a C++ header.
- `live_angle_plot.py`: A live visualization tool. Run this while the Arduino is plugged in to see a real-time plot of the fully synthesized, perfectly linear 0-360 degree angle output!
- `sensor_reader/sensor_reader.ino`: The raw Arduino data logger script used to stream the raw ADC values over serial.
- `encoder_decoder/encoder_decoder.ino`: The FINAL Arduino skeleton sketch. It includes the generated header and actually uses the math (5-parameter + LUT + Lissajous startup voting) to output continuous, highly accurate mechanical angle in real-time.
- `encoder_decoder/calib_constants.h`: The auto-generated PROGMEM header containing all calibration parameters (Generated by running the Python script).

## How it works
1. **5-Parameter Math (No LUT):** The script first fits a 5-parameter ellipse (offsets, amplitudes, and phase delta) to center and normalize the raw sensor data to a perfect unit circle.
2. **4Pi LUT (With LUT):** Because the magnets are not perfect and cause ripples in the speed, the script builds a 720-bin (4Pi electrical) kinematic velocity look-up table by assuming the macroscopic speed over 10 seconds is the "true" speed.
3. **Tracking & Silent Phase Correction:** Because 2-pole pair encoders have a 180-degree physical ambiguity, the Arduino takes a best-effort guess at boot and instantly starts outputting continuous angle data so your PID loop doesn't explode. Meanwhile, the Python script has calculated a "Safe Zone" (the electrical angle where the signatures are furthest apart). As the wheel turns, the Arduino waits until it hits this Safe Zone. It then verifies if its initial guess was right. If it guessed wrong, it silently flips the phase in the background and absorbs the jump in a display offset, meaning your ROS controller sees **perfectly continuous odometry with zero jumps**, but the ripple magically disappears mid-drive!

## Usage
1. Generate the calibration header from your CSV:
```bash
uv run python calibrate_and_plot.py
```
2. Flash `encoder_decoder/encoder_decoder.ino` to your Arduino.
3. The Arduino will instantly stream continuous data. You can watch the Serial monitor as you manually spin the wheels; it will print `[DEBUG]` messages confirming exactly when each wheel hits its safe zone and whether its initial boot guess was confirmed or corrected.
4. **Live Visualization:** Close the Arduino Serial Monitor and run:
```bash
uv run python live_angle_plot.py
```
This will open a live graphing window showing the fully corrected, perfectly linear sawtooth angle (mod 360) in real-time. (Note: It also prints the `[DEBUG]` homing messages to your console so you can see when the phases lock).
